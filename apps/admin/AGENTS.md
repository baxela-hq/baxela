# AGENTS.md

Guidelines for AI agents working in this repository. Read this before making changes.

## Project Overview

**Baxela-admin** — the admin panel of the Baxela e-commerce platform. It is a fork of the
[shadcn-admin](https://github.com/satnaing/shadcn-admin) template (v2.2.1, keep this in mind:
template/demo code and real Baxela modules coexist — see [Template vs Baxela Modules](#template-vs-Baxela-modules)).

- **SPA** talking to a Laravel backend (`VITE_API_BASE_URL`), currently `http://Baxela-backend.local/api/v1`.
- UI language defaults to **Farsi (`fa`)**, fallback `en`. Full **RTL support** (direction is a manual UI
  preference, decoupled from i18n language).
- **Multilingual by design**: `en`/`fa` are simply the locales shipped today — the whole structure
  (i18n namespaces, `public/locales/`, per-entity `translations[]`, the backend-driven language list)
  is built to support more languages later. Never assume only en/fa exist.
- Package manager: **pnpm**.

## Commands

```bash
pnpm install        # install deps
pnpm dev            # dev server (Vite)
pnpm build          # tsc -b && vite build  ← this IS the typecheck; there are no tests
pnpm lint           # eslint
pnpm format         # prettier --write .
pnpm format:check   # prettier --check .
pnpm knip           # unused code/files/deps check
```

Always run `pnpm build` (typecheck) and `pnpm lint` before finishing a task. There is no test suite.

**Commits:** Conventional Commits (`feat:`, `fix:`, `refactor(scope):`, …) — configured via `cz.yaml`
(commitizen). Scope is usually the module, e.g. `feat(media):`, `refactor(catalog):`.

## Never Edit / Generate

- `src/routeTree.gen.ts` — generated by `@tanstack/router-plugin` from `src/routes/`. Never touch.
- `src/components/ui/*` — vendored shadcn/ui. Many are **customized for RTL** (dialog, dropdown-menu,
  select, table, sheet, sidebar, switch, …) and some are generally modified (scroll-area, sonner,
  separator). Re-running `shadcn add` over them destroys customizations. Also **ignored by ESLint**.
- `pnpm-lock.yaml` — only via pnpm.
- Dead code (do not extend, do not copy patterns from): `src/routes/clerk/**` — an optional,
  self-contained Clerk demo tree independent of the real JWT auth.

Cleanest reference implementations: `src/features/catalog/categories/` (list + drawer CRUD) and
`src/features/catalog/products/` (list + full-page form). Follow this structure for new modules:


## API Layer Conventions

`src/shared/lib/api-client.ts` exports `getRequest/postRequest/putRequest/patchRequest/deleteRequest`.
Bearer token is injected from the auth store; 401 resets auth and redirects to `/sign-in?redirect=…`.

In `api/<entity>.api.ts`:

```ts
const BASE_URL = 'catalog/admin/categories'   // '<module>/admin/<resource>', NO leading slash

fetchCategories(queryParams)          // getRequest<PaginatedResponse<Category>>(BASE_URL, params)
fetchOneCategory(id)                  // getRequest<SingleResponse<T>>, unwraps { data }
createCategory(form) / updateCategory(id, form)   // post/patch, unwrap SingleResponse
deleteCategory(id)                    // deleteRequest(`${BASE_URL}/${id}`)
```

- Verb naming: `fetchX` / `fetchOneX` / `createX` / `updateX` / `deleteX` — consistent across all
  modules (e.g. `fetchPages`, `fetchSettings`, `fetchUsers`). Keep it that way in new modules.
- Nested resources take parent id first, e.g. option-values: `catalog/admin/options/$id/values`.
- Uploads use `FormData` with explicit `'Content-Type': 'multipart/form-data'` header.

**Response envelopes** (`src/shared/types/common.types.ts`, Laravel-style):

```ts
SingleResponse<T>      { data: T }
AllResponse<T>         { data: T[] }
PaginatedResponse<T>   { data: T[], meta: { total, per_page, current_page, last_page, from, to, ... } }
```

Table `pageCount` = `data.meta.last_page`.

## TanStack Query Conventions

- Server state and mutations live in **per-feature hooks**, not inline in components:
  `hooks/use-<entity>.ts` (queries) and `hooks/use-<entity>-mutations.ts` (mutations).
  Components consume the hooks and contain no `useQuery`/`useQueryClient` logic.
- Query hooks keep the canonical keys: list `queryKey: [CACHE_KEY, search]`
  (search = full URL search object), detail `[CACHE_SINGLE_KEY, id]`.
- Languages (translatable forms): `useLanguages()` from
  `@/features/core/languages/hooks/use-languages` (shared key `['languages']`).
  Currencies: `useCurrencies()` from `@/features/core/currencies/hooks/use-currencies`.
- Mutation hooks (`useSaveX` / `useDeleteX` / `useBulkDeleteX`) encapsulate the whole flow:
  API call → `toast.success(tMessage('success.record.…', { name }))` →
  `await queryClient.invalidateQueries({ queryKey: [CACHE_KEY] })`, and
  `onError`: `if (err instanceof ApiError) parseAndToastError(err)` else
  `toast.error(tMessage('error.general'))`.
- Components call `mutation.mutate(variables, { onSuccess: … })` for the pure-UI aftermath
  only (close dialog, `form.reset()`, redirect). Per-call callbacks run after (and await)
  the hook-level ones, so ordering is preserved. Do NOT re-implement toasts in components.
- Naming: `use<Entity>List(search)` / `useOne<Entity>(id)` / `use<Entity>Tree(excludeId)` for
  queries; `useSave<Entity>()` (create+update) / `useDelete<Entity>()` / `useBulkDelete<Entity>()`
  for mutations.
- Global defaults (in `src/main.tsx`): `staleTime: 10_000`, global mutation `onError: handleServerError`
  — a backstop only; a hook-level `onError` replaces it (v5 spread-merges defaults).
- Status maps for badges stay in `data/data.ts`; translated-field display uses
  `pickTranslation(translations)` from `@/shared/lib/locale` (never hand-roll the
  `getDefaultLanguage` index dance). Tree selects use `buildHierarchy`/`excludeSubtree`
  from `@/shared/lib/tree`.
- All real modules follow this (canonical reference: `catalog/categories`). Full-page
  forms additionally keep **pure domain modules** next to the schema
  (`products/data/variant-matrix.ts`, `products/data/attribute-grouping.ts`) and reuse
  cross-feature picker hooks: `useCategoryTree` (categories), `useOptionsAll` (options),
  `useAttributeOptions` (attributes), `useAttributeGroupOptions` (attribute-groups),
  `useActiveAttributeTemplates` + `useAttributeValueOptions` (attribute-templates/-values).

## Routing Conventions

- Route files in `src/routes/` are thin: `createFileRoute('<id>')({ component: FeatureComponent })`,
  component imported from `features/`. No default exports, no loaders, no `beforeLoad`.
- The route id string must exactly mirror the on-disk path including group/underscore segments and a
  **trailing slash for index routes**: `'/_authenticated/catalog/products/'`.
- Feature components get route APIs at module level:
  `const route = getRouteApi('/_authenticated/catalog/products/')` then `route.useSearch() / useNavigate() / useParams()`.
- Navigation constants live in `data/routes.ts` (`FeatureRoutes.CREATE/EDIT/LIST` with `$id` placeholder,
  replaced via `.replace('$id', id)`).
- **Auth is reactive, not route-guarded**: no `beforeLoad` anywhere. Protection = axios 401 interceptor +
  QueryCache `onError` in `main.tsx`. Real auth is JWT (`/auth/public/auth/signin`); Clerk tree is separate demo.
- Deleting a URL param requires explicitly setting it to `undefined` in the `navigate({ search: prev => ({...prev, key: undefined}) })` patch.
- Known gap: most real list routes define **no `validateSearch`** (only template routes + media do), so
  search params are unvalidated. When adding a new route, adding a `validateSearch` zod schema is the
  improvement direction, but stay consistent with sibling modules.

## Data Table Conventions (server-driven)

Every list table: `manualPagination: true, manualSorting: true, manualFiltering: true`,
`pageCount: data.meta.last_page`. URL state is the single source of truth via
`useTableUrlState` (`src/hooks/use-table-url-state.ts`):

```ts
useTableUrlState({
  search, navigate,                                  // from route.useSearch()/useNavigate()
  pagination: { defaultPage: 1, defaultPageSize: 10 },  // URL keys: page, pageSize (omitted when default)
  globalFilter: { enabled: false },
  columnFilters: [
    { columnId: 'title', searchKey: 'filter[title]', type: 'string' },
    { columnId: 'status', searchKey: 'filter[status]', type: 'array' },
  ],
  sorting: { key: 'sort' },                          // '-id' = desc; default [{ id: 'id', desc: true }]
})
```

- Backend filters use **Laravel-style `filter[field]` params**; the whole `search` object is passed
  verbatim to the API fetch (so it becomes the query string).
- URL key is `pageSize`, but ad-hoc large fetches use `per_page` (e.g. `{ per_page: 1000 }` for selects) — backend expects `per_page`.
- Columns (`columns.tsx`): leading `select` checkbox column (no sort/hide), `DataTableColumnHeader`,
  status → `<Badge>` with color from `data/data.ts` map, trailing `actions` column with `DataTableRowActions`.
  Per-column styling via `meta: { className, thClassName, tdClassName }` (augmented in `src/tanstack-table.d.ts`).
- Translated columns: `{ id: 'title', accessorKey: 'translations', cell: row => row.translations[getDefaultLanguage(...)].title }`.
- Shared building blocks from `@/components/data-table` (Toolbar with 400ms-debounced search, Pagination,
  FacetedFilter, ViewOptions, BulkActions, ColumnHeader) — reuse, don't reimplement.

## Forms & Dialogs

- Dialog state: `components/provider.tsx` context over `useDialogState<DialogType>()` (toggle semantics)
  plus `currentRow`. Exported as `use<Entity>` (e.g. `useCategories`).
- `components/dialogs.tsx` is the only place dialogs render; `open={open === 'edit'}`;
  `onOpenChange` clears `currentRow` in a `setTimeout(..., 500)` (wait for close animation).
- Create/edit UI = `MutateDrawer` (Sheet) for entities, centered `Dialog` for media.
- Forms: `useForm<FormValues>({ resolver: zodResolver(formSchema), defaultValues })` with shadcn
  `Form/FormField/…`. Non-translatable: `defaultValues: currentRow ?? defaultValues`.
  Translatable: `buildDefaultValues(languages)` + `useEffect(() => form.reset(buildEditValues(languages, currentRow)))`.
- Destructive confirms wrap shared `ConfirmDialog`: single delete types the record **id**,
  bulk delete types **DELETE**.

## i18n Conventions

- **Multilingual by design.** `en` + `fa` are the locales available today, but treat
  `public/locales/` as an **open set** — more languages will be added. Any key change must be applied
  to **every** locale folder; never rely on English/Farsi-specific grammar, text direction, or
  hardcoded language lists in code.
- Namespaces = file path under `public/locales/{lang}/`: `shared/common`, `shared/data-table`,
  `shared/layout`, `catalog/product`, `catalog/category`, `catalog/option`, `catalog/option-value`,
  `content/page`, `media/media`, `order/order`, `setting/setting`, `user/user`.
- **Every user-facing string must be translated.** Use `useAppTranslation(namespace)` — never raw `useTranslation`:

  `tLabel('title')` → `form.labels.title` · `tAction` → `form.actions.*` · `tPlaceHolder` → `form.placeholders.*` ·
  `tStatus('status.in_stock')` → `form.statuses.*` (nested) · `tTooltip` → `form.tooltips.*` ·
  `tHelpText` → `form.help_texts.*` · `tMessage('success.record.deleted', { name })` → `messages.*` ·
  `tPageTitle('index.title')` → `page_titles.*`

- Translation JSON mirrors these prefixes (`form.labels`, `form.statuses`, `messages`, `page_titles`).
  When adding labels/statuses, update **every language folder** under `public/locales/` (currently
  `en` and `fa`) — locale files must stay in parity; a key missing from one language is a bug.
- Entity name object: `const entityName = { singular: tLabel('product'), plural: tLabel('products') }`.
- There is currently NO runtime language switching (`i18n.changeLanguage` never called; `lng` is
  fixed at `fa` in `src/i18n/index.ts`). This is present state, not a design limit — the setup is
  standard i18next, and a language switcher is expected to come; don't build anything that would
  block it.

### Toast/message keys — reuse shared generics, never invent new message keys

ALL mutation/toast feedback lives in `shared/common.json` under `messages.*` (kept in sync across
**every** locale folder), shared by every module. Per-module namespaces (`catalog/product.json`, …)
must **not** contain a `messages` section. Always take `tMessage` from `useAppTranslation(Locales.SHARED_COMMON)`.

Before writing any toast message:

1. **Read `messages` in `shared/common.json` first** (in each locale folder).
2. Use the generic CRUD family with `{{name}}` interpolation — this covers ~all cases:
   ```tsx
   toast.success(tMessage(`success.record.${isUpdate ? 'updated' : 'created'}`, { name: entityName.singular }))
   toast.success(tMessage('success.record.deleted', { name: entityName.singular }))
   toast.success(tMessage('success.record.deleted_general'))           // no name available
   toast.error(tMessage('error.general'))                              // fallback on non-ApiError
   // also available: error.api, error.validation, error.record.not_found, error.record.already_exists
   ```
3. For an action the family doesn't cover (e.g. upload, restore), use the fully-generic fallback that
   already exists — `success.default` = `"The {{name}} was {{action}} successfully."` and
   `error.default` — passing a **translated** verb as `action`. Do NOT add a new specific key.
4. Add a new key to `shared/common.json` only when the sentence shape is genuinely different
   (like `success.upload_general`) — and then add it to **every** locale folder (`en`, `fa`, and
   any future locale).

## Multi-Language Content (translatable entities)

Backend entities carry `translations: Translation[]` (`{ language_id, language (code), title, slug, … }`).

- Available languages come from `core/admin/languages` (`fetchLanguages()`, shared query key `['languages']`).
  **This list is dynamic** — never hardcode a language set in forms, columns, or logic; always render
  from this query. A new language added on the backend automatically appears as a new form tab.
- Form schema embeds `translations: z.array(translationSchema)`; UI renders one `<Tabs>` trigger per
  language (`value={language.code}`), fields named `translations.${index}.title` etc.
- `buildDefaultValues(languages)` seeds one empty translation per language;
  `buildEditValues(languages, row)` merges existing translations by language code.
- Display value of a translated field: `translations[getDefaultLanguage(translations)]` (from
  `src/shared/lib/locale.ts`, keyed off the stored default language).

## Client State & Providers

- Provider order in `main.tsx`: `StrictMode > QueryClientProvider > ThemeProvider > FontProvider > DirectionProvider > RouterProvider`.
- Authenticated layout: `SearchProvider > LayoutProvider > SidebarProvider > AppSidebar + SidebarInset > Outlet`.
- `Header` and `Main` are rendered **per page** (imported from `@/components/layout/header|main`), not in the layout route.
- UI preferences persist in **cookies** via providers: `vite-ui-theme` (dark/light/system),
  `dir` (ltr/rtl), `font`, `layout_variant`/`layout_collapsible`. Access via `useTheme()/useDirection()/useFont()/useLayout()`.
- Auth store: zustand + persist, localStorage key `auth-storage`; token additionally mirrored to a
  cookie; `reset()` clears both. Sign-out = `useAuthStore.getState().reset()`.

## UI Principles

- shadcn "new-york" style; composition of `@/components/ui` primitives. Use existing shared
  components (`@/components/data-table`, `ConfirmDialog`, `TiptapEditor`, `image-uploader`,
  `skeleton-widget`) before writing new ones.
- **RTL-aware styling is mandatory**: use logical utilities (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`,
  `rtl:`/`ltr:` variants), never `ml-/mr-/left-/right-` in feature code. Direction flips Radix popovers too.
  Future languages may be either direction — logical utilities keep pages direction-agnostic.
- Icons: `lucide-react`, `size={16}` typical for inline icons. Brand icons from `src/assets/brand-icons`.
- Status badges: color classes mapped in `features/<entity>/data/data.ts` — extend the map, don't inline.
- Layout: `Header` (fixed, blur-on-scroll) + `Main` (supports `fixed`/`fluid` props) per page; page title +
  `PrimaryButtons` above the table; `Skeleton` while loading.
- Tailwind v4: theme via CSS variables in `src/styles/theme.css`; class sorting handled by
  `prettier-plugin-tailwindcss` — run `pnpm format` rather than hand-ordering classes.

## Code Style & Lint Rules (enforced)

- Prettier: no semicolons, single quotes (JSX too), 2-space, width 80, trailing comma `es5`;
  imports sorted by `@trivago/prettier-plugin-sort-imports` (run `pnpm format`).
- ESLint: `no-console` is an **error**; unused vars must be prefixed `_`; type-only imports enforced
  (`import { type Foo }` inline style); no duplicate imports. Ignores: `dist`, `.vite`, `.tanstack`
  (cache dirs), `src/components/ui`.
- TypeScript strict + `noUnusedLocals`/`noUnusedParameters` — the build fails on violations.
- Components in feature files: named exports, files `kebab-case.tsx`; zod schemas/types `PascalCase`;
  constants classes in `data/routes.ts` use `SCREAMING_SNAKE` static members.
- `src/components/ui/**` is ESLint-ignored; everywhere else the above applies.

## Known Gotchas (avoid repeating these mistakes)

1. Route-id strings (in `createFileRoute` and `getRouteApi`) must match **exactly**, including the
   trailing slash on index routes — a mismatch silently breaks search/navigate.
2. Tiptap "Insert image" opens the **media picker** (`media-picker-dialog.tsx`, single-select,
   `accept="image/*"`) and inserts the media URL — no local-file/base64 uploads. Note this makes
   `src/components/tiptap/tiptap-editor.tsx` (shared) import from `features/media/` — an
   intentional shared→feature dependency: the media picker is the designated reusable picker.
3. `image-uploader.tsx` uses manual `useEffect` fetching (its react-query version is commented out) —
   deliberate endpoint-driven component with `$id` placeholder endpoints.
4. Most Baxela feature files are **not prettier-formatted** (mixed styles predating the current
   config — verified on git history). Don't hand-format in feature PRs; a dedicated repo-wide
   `pnpm format` commit is the fix when desired.
5. The `options` form intentionally has **no `description` field** — the backend schema for option
   translations only accepts `title` + `slug`. Don't re-add it unless the API contract changes.

## Definition of Done

- `pnpm build` passes (typecheck) and `pnpm lint` is clean (no `console.log`, no unused vars).
- New strings added to **every** locale folder under `public/locales/**` (currently `en` and `fa` —
  the set is open, keep all locales in parity) following the `form.*` / `page_titles.*` structure.
